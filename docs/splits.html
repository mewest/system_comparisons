Reviewed events are analyst-reviewed onsite events (status preliminary, reviewed or final). Every other onsite event within ±3 min of a reviewed event is a test event: its first-arriving P picks are compared with the arrival times predicted from the reviewed event's hypocenter (ak135). RMS is the root-mean-square of those residuals in seconds. If it is small, the reviewed event already explains the test event's picks and the test event is likely a split (duplicate solution). If it is large, the test event needs its own source. Labels for checking the thresholds: rejected (test event rejected on onsite) and both reviewed (the test event is also a reviewed event, so the analyst kept both).

How the RMS test works

Each panel shows one pair as a record section. The black line is the P arrival time predicted with ak135 from the reviewed event's hypocenter, at each distance from it. ○ are the reviewed event's own P picks, ● the test event's P picks, and the thin vertical lines their residuals (observed − predicted). RMS is the root-mean-square length of those lines. For a split, the test event's picks fall on the reviewed event's curve; for a distinct event they sit off it, typically shifted by the difference in origin time and scattered by the difference in location.
